# 清除全部本地数据

版本：1.40 / 116。

## 入口和流程

设置页底部新增“清除缓存”，位于退出登录上方。这里的“缓存”指本应用的全部本地数据，而不是只删除可重新下载的教室列表。

1. 首次点击只说明删除范围、不可恢复以及应用会关闭，用户可以取消。
2. 确认后手动输入**当前登录账号**和教务密码，不自动填充已记住的密码。
3. 联网校验身份。其他账号、错误密码、网络错误、取消校验或账号已切换，均不能触发清理。
4. 通过后向 Android 提交本应用的数据重置请求。系统停止应用；用户重新打开后回到初始登录状态，演示和账号使用指引重新生效。

演示、未登录及指引练习不能清除正式数据。指引最后一章增加一条说明步骤，只介绍功能，不要求输入密码、联网校验或实际清除。

## 删除范围

- 登录令牌、保存的账号密码、用于确认当前账号的加密元数据。
- 两校区教室数据库缓存和收藏、标签、备注、插座、排除等个人标记。
- 筛选、楼宇选择、标签词条、规划偏好及保存的时段组合。
- 主题、深色模式、默认校区、时段条和节次编号等设置。
- 账号 / 访客使用指引记录，以及本应用内部和应用专属外部存储中的动态缓存、文件。

不会卸载应用、删除学校账号或修改学校服务端数据；不会删除用户另行导出至公共目录的文件，也不声称删除平台已有的历史云备份。

## 安全边界

身份校验使用独立的教务登录请求，丢弃返回的令牌，不调用会先清空旧会话的普通登录流程。本次输入不写入偏好、ViewModel、保存状态或日志；点击提交立即清空密码输入框。校验被取消后，即使收到迟到的成功结果也不能继续清理。

新登录会单独加密保存当前账号，即使未勾选记住密码也能核对身份；这不保存密码，也不授权自动登录。旧会话优先使用已保存凭据中的账号，必要时只读核对指引使用的本地账号 HMAC。无法确认旧账号时拒绝清理并提示重新登录，不放宽为任意有效账号。

最终调用 [ActivityManager.clearApplicationUserData](https://developer.android.com/reference/android/app/ActivityManager#clearApplicationUserData())，由系统完整重置本应用数据并终止进程，避免手动清文件后被正在运行的写入任务恢复。返回值只表示请求是否被接受，不提前报告“删除完成”；系统拒绝时保留原数据，重试必须重新校验。

## 实现及验证

- `ui/SettingsScreen.kt`、`ui/CacheClearDialog.kt`：入口、两级确认和临时凭据。
- `ui/YOURoomViewModel.kt`：阶段约束、账号匹配、取消与会话失效保护。
- `data/SchoolSession.kt`、`data/local/SessionStore.kt`：独立校验和加密账号元数据。
- `data/local/AndroidUserDataReset.kt`：仅对本应用提交系统清理请求。
- `ui/GuideSteps.kt`：非交互的清理说明；共 45 步。不改变已有完成 / 跳过用户的重播策略。

自动测试不连接学校服务。系统重置探针仅允许 `com.example.youroom.uitest` 隔离包及模拟器，使用虚构凭据、数据库、偏好和文件；分次执行准备、系统清理和重开验证，绝不对正式安装或真实手机执行。
